# DESIGN.md

## 1. Отмена устаревших запросов

**Как устроено.** `createSearchController.input()` вызывается на каждое изменение поля и
первым делом делает `active.abort()`. Это происходит сразу, а не когда debounce запустит
новый запрос, поэтому устаревший ответ не успеет прилететь за время ожидания debounce.
Следующий запрос получает новый `AbortController`. В `searchCountries` сигнал вызывающего
объединяется с `AbortSignal.timeout(ms)` через `AbortSignal.any`, и результат уходит в `fetch`.

В `catch` ветки различаются по `error.name`:

| Источник                   | `name`         | Реакция              |
| -------------------------- | -------------- | -------------------- |
| Наш `abort()` (новый ввод) | `AbortError`   | молча игнорируем     |
| Таймаут                    | `TimeoutError` | ошибка + «Повторить» |
| `HttpError` (не 404)       | `HttpError`    | ошибка + «Повторить» |

**Почему не флаг «актуальный ли ответ».** Флаг решает только отображение: запрос продолжает
занимать соединение, парсить тело и тратить трафик, а медленный `sp` конкурирует с нужным `spain`.
`abort()` реально обрывает запрос и освобождает соединение. Флаг оставлен только как страховка
после `await` (`controller.signal.aborted`), потому что ответ из кэша может разрешиться в
микротаске раньше abort.

**Кэш и дедупликация.** Сетевой запрос в `requestCache.ts` имеет собственный `AbortController`,
не принадлежащий никому из вызывающих. Каждый вызывающий получает отдельный промис со своим
сигналом. Отмена одного отклоняет только его промис. Запрос обрывается в сети, лишь когда
счётчик подписчиков упал до нуля. Ошибки и отмены не кэшируются, пустой результат (404) кэшируется.

## 2. Задержка debounce = 300 мс

Типичный интервал между нажатиями при уверенном наборе составляет 150–250 мс, поэтому 300 мс
склеивает серию нажатий в один запрос и не даёт заметной задержки реакции (порядка 0,3 с).

- **Без debounce:** запрос на каждый символ (`s`, `sp`, `spa`…), лишняя нагрузка на API, мерцание
  индикатора загрузки и множество отмен.
- **Слишком большая (≥ 800 мс):** интерфейс кажется «зависшим», пользователь ждёт
  и не понимает, что поиск работает.

Значение вынесено в `DEFAULT_DEBOUNCE_MS` и внедряется через зависимости, поэтому
легко настраивается и тестируется.

## 3. Сложность (Big O)

- `mapCountryResponse`: O(L + B + C) на одну страну (языки, границы, валюты), на практике O(1),
  так как поля ограничены. Для массива из n стран это O(n·k). Память O(L + B + C) на результат.
  Функция чистая, без побочных эффектов.
- Кэш: `get`/`set` O(1) в среднем (`Map`), вытеснение самой старой записи O(1)
  (порядок вставки в `Map`), память O(maxEntries).
- Дедупликация: поиск запроса «в полёте» O(1); подписка и отписка вызывающего O(1).
- История: `addToHistory` O(h), где h ≤ 8, то есть константа.

## 4. Принципы чистого кода

- **Чистые функции** (`mapCountryResponse.ts`, `history.ts: addToHistory`, `normalizeQuery.ts`):
  результат зависит только от аргументов, входные данные не мутируются.
- **Функции высшего порядка и замыкания** вместо классов (`debounce.ts`, `requestCache.ts`,
  `searchController.ts`). Единственный класс — `HttpError`, потому что ТЗ требует `extends Error`.
  Изменяемое состояние (`timer`, `cache`, `active`) спрятано в замыкании, наружу отдаются только
  замороженные наборы функций (`Object.freeze`).
- **Внедрение зависимостей** (`makeSearchCountries(fetcher)`, `createSearchController({search, history, debounceMs})`):
  ядро не знает про DOM и сеть, поэтому тестируется без браузера. Сборка в `main.ts`.
- **Single Responsibility:** `core/` не знает про DOM, `ui/` не знает про сеть, каждый файл решает одну задачу.
- **Иммутабельное состояние:** `setState` создаёт новый объект, UI сравнивает ссылки и перерисовывает
  только изменившиеся части (`app.ts`).
- **Безопасность:** Компоненты в `ui/` добавляются в DOM с помощью метода `append()` - безопасный способ добавления узлов (nodes) и текста в конец родительского элемента, `innerHTML` не используется.
- **Явные состояния:** тип `SearchView` (discriminated union) исключает невозможные комбинации
  вроде «загрузка + ошибка».
